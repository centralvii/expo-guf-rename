# План разработки веб-приложения для пакетного переименования файлов (.guf)

Данный документ содержит подробный, пошаговый план разработки production-ready приложения (React + TypeScript + Vite) для пакетного переименования файлов, извлекаемых из ZIP-архива.

**Важно:** Для соответствия требованиям процесса, после выполнения каждой задачи (или подзадачи) необходимо выполнить `git commit` с указанным комментарием, а затем `git push` в текущий репозиторий. Проект не будет реализовываться автоматически на данном этапе, это только план.

---

## Этап 1: Инициализация и настройка проекта

### Задача 1.1: Развертывание базового каркаса
- **Описание:** Инициализировать проект с помощью `npm create vite@latest . -- --template react-ts`. Настроить `tsconfig.json` и минимальную структуру директорий (`src/components`, `src/utils`, `src/types`, `src/hooks`). Очистить шаблонный код Vite.
- **Commit:** `chore: инициализация проекта React+TS через Vite, базовая структура директорий`

### Задача 1.2: Установка зависимостей
- **Описание:** Установить ключевые библиотеки для работы:
  - `jszip` (для работы с ZIP)
  - `file-saver` (для скачивания итогового архива)
  - `@dnd-kit/core`, `@dnd-kit/sortable`, `@dnd-kit/utilities` (для Drag-and-Drop)
  - Пакеты для стилизации (например, Tailwind CSS, Lucide-react для иконок).
- **Commit:** `chore: установка базовых зависимостей (jszip, file-saver, dnd-kit, tailwind)`

### Задача 1.3: Определение структуры данных (Типы)
- **Описание:** Создать файл `src/types/index.ts`. Реализовать интерфейс `FileRow`, указанный в промпте (id, order, originalPath, cleanName, поля префиксов и т.д.). Вынести дефолтный шаблон в константы.
- **Commit:** `feat: определение интерфейсов данных (FileRow) и констант проекта`

## Этап 2: Разработка бизнес-логики и утилит (Без UI)

### Задача 2.1: Модуль парсинга и очистки имени файла
- **Описание:** Создать `src/utils/nameCleaner.ts`. Реализовать функцию `cleanName`, которая с помощью регулярных выражений будет удалять дату (YYYY-MM-DD), время (HH-MM-SS), префиксы (например, «ДО.»), а также корректировать двойные пробелы по краям и лишние разделители.
- **Commit:** `feat: реализация утилиты cleanName для очистки исходных названий файлов`

### Задача 2.2: Движок шаблонов имен (Template Engine)
- **Описание:** Создать `src/utils/templateEngine.ts`. Разработать функцию, которая принимает `FileRow` и строку шаблона (`templateString`) и возвращает готовое `newName`. Должна поддерживать замену тегов `{index}`, `{indexPad6}`, `{originalName}`, `{extension}`, `{date}`, `{time}`, `{cleanName}`, `{prefix}`, `{module}`, `{code}`, `{docNumber}`, `{custom1}`, `{custom2}`.
- **Commit:** `feat: разработка templateEngine для замены тегов в шаблоне имени`

### Задача 2.3: Модуль валидации перед экспортом
- **Описание:** Создать `src/utils/validation.ts`. Написать функцию для проверки списка файлов перед архивацией. Проверки: наличие пустых имен, наличие дублирующих имен, поиск запрещенных символов OS (`\ / : * ? " < > |`), проверка расширений (что они не потеряны).
- **Commit:** `feat: механизм валидации итоговых имен файлов (дубликаты, спецсимволы, пустые имена)`

### Задача 2.4: Обработка ZIP-архивов (Импорт / Экспорт)
- **Описание:** Создать `src/utils/zipHandler.ts`. Реализовать: 
  - `extractZip(file: File)` — асинхронное чтение загруженного ZIP (с поддержкой вложенных папок), извлечение файлов (`.guf`), генерация первичных объектов `FileRow`.
  - `generateZip(files: FileRow[])` — упаковка обратно в ZIP с новыми валидными именами и вызов `file-saver` для скачивания.
- **Commit:** `feat: реализация импорта и экспорта ZIP-архивов с сохранением Blob`

## Этап 3: Разработка UI-компонентов и управления состоянием

### Задача 3.1: Зона загрузки архива (Uploader)
- **Описание:** Разработать компонент `FileUploader.tsx`. Должна быть поддержка Drag-and-drop архива, а также кликабельная зона для системного окна выбора файла. Интеграция с `extractZip`. Возникающие ошибки (неверный формат) должны отлавливаться.
- **Commit:** `feat: компонент FileUploader и интеграция загрузки архива`

### Задача 3.2: Глобальное состояние приложения 
- **Описание:** Создать хук или использовать React Context для хранения массива `files: FileRow[]` и `templateString`. Реализовать методы мутаций: обновить поле у файла, обновить весь шаблон, пересчитать `order` и новые имена для всех файлов. Сделать так, чтобы при любом изменении пересчитывалось превью (newName).
- **Commit:** `feat: подключение глобального стейта для списка файлов и шаблона`

### Задача 3.3: Таблица файлов и интеграция Drag-and-Drop
- **Описание:** Разработать компоненты `FileTable.tsx` и `FileTableRow.tsx`. Вывести данные `FileRow`. Использовать библиотеку `@dnd-kit` для реализации возможности перетаскивания строк (изменение `order`). После перетаскивания должен производиться автоматический перерасчет индексов ({index}).
- **Commit:** `feat: компонент таблицы файлов с реализацией Drag-and-Drop перетаскивания`

### Задача 3.4: Редактор строк (Инпуты в таблице)
- **Описание:** Внутри строк реализовать инпуты для редактирования кастомных полей файлов: `prefix`, `module`, `code`, `docNumber`, `custom1`, `custom2`. Все изменения должны реактивно обновлять `newName` (превью) в реальном времени.
- **Commit:** `feat: редактирование пользовательских полей файла напрямую в таблице`

### Задача 3.5: Редактор шаблона и быстрые теги
- **Описание:** Создать компонент `TemplateEditor.tsx`. Поле для ввода шаблона со сбросом к дефолтному. Разместить кнопки для быстрой вставки доступных `{tag}` в строку.
- **Commit:** `feat: редактор шаблона наименования и кнопки быстрой вставки тегов`

### Задача 3.6: Блок массовых действий
- **Описание:** Реализовать компонент `MassActions.tsx`. Формы для массового заполнения атрибутов для всех загруженных строк. Добавить кнопку "Заполнить порядковые номера" для автоматического проставления нумерации.
- **Commit:** `feat: панель массовых действий и автоматического проставления порядковых номеров`

### Задача 3.7: Индикатор ошибок и логика визуализации валидации
- **Описание:** Добавить компонент `ValidationPanel.tsx`. Если валидация выявила дубликаты имен или незаконные символы — подсвечивать строки с ошибками красным, блокировать возможность скачать итоговый ZIP, отображать понятный текст ошибки пользователю.
- **Commit:** `feat: UI индикация ошибок валидации и блокировка выгрузки архива`

### Задача 3.8: Интеграция экспорта
- **Описание:** Разрулить финальную кнопку "Скачать переименованный архив". При нажатии вызывается `generateZip`. Добавить состояние загрузки (loader) на период упаковки ZIP.
- **Commit:** `feat: интеграция финальной кнопки скачивания переименованного ZIP-архива`
