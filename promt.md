Сделай современное веб-приложение для пакетного переименования файлов `.guf` из ZIP-архива.

Требования к стеку:
- React
- TypeScript
- Vite
- современный UI
- без backend, полностью клиентское приложение
- приложение должно работать в браузере
- должно подходить для деплоя на GitHub Pages или Vercel

Главная задача:
Пользователь загружает ZIP-архив, приложение извлекает из него файлы, показывает их в виде таблицы или списка, позволяет менять порядок файлов drag-and-drop, задавать шаблон переименования через теги в формате `{tag}`, а затем скачивать новый ZIP с уже переименованными файлами.

Функциональные требования:

1. Загрузка ZIP
- Пользователь может загрузить ZIP-файл через input или drag-and-drop
- Приложение должно распаковать ZIP прямо в браузере
- Нужно извлечь все файлы из архива
- Желательно отображать только файлы `.guf`, но архитектура должна позволять работать и с любыми другими файлами
- Вложенные папки в ZIP тоже должны корректно обрабатываться

2. Отображение файлов
- После загрузки архива показать таблицу файлов
- Для каждой строки отобразить:
  - текущий порядок
  - исходное имя файла
  - расширение
  - очищенное имя `cleanName`
  - пользовательские поля для переименования
  - превью нового имени
- Таблица должна поддерживать drag-and-drop перестановку строк
- При изменении порядка должен пересчитываться индекс

3. Шаблон переименования
- Пользователь задает шаблон нового имени в формате:
  `{indexPad6}_{prefix}_{module}_{code}_{date}_{time}_{cleanName}`
- Нужно реализовать движок шаблонов, который заменяет теги на значения из строки
- Поддерживаемые теги:
  - `{index}`
  - `{indexPad6}`
  - `{originalName}`
  - `{extension}`
  - `{date}`
  - `{time}`
  - `{cleanName}`
  - `{prefix}`
  - `{module}`
  - `{code}`
  - `{docNumber}`
  - `{custom1}`
  - `{custom2}`

4. Очистка имени файла
- Нужно реализовать функцию `cleanName`, которая очищает исходное имя файла от технических префиксов
- Например из строки:
  `2026-04-17_16-16-17-ДО. Связь атрибута и алгоритма для сервисного действия вычисление значения атрибута-Состояние БГ`
  нужно получить:
  `Связь атрибута и алгоритма для сервисного действия вычисление значения атрибута-Состояние БГ`
- Очистка должна:
  - убирать дату в начале имени в формате `YYYY-MM-DD`
  - убирать время в начале в формате `HH-MM-SS`
  - убирать служебные префиксы типа `ДО.`
  - убирать лишние разделители в начале
  - убирать двойные пробелы
  - обрезать пробелы по краям

5. Редактирование данных
- Пользователь должен иметь возможность вручную редактировать поля:
  - `prefix`
  - `module`
  - `code`
  - `docNumber`
  - `custom1`
  - `custom2`
- Нужен блок массового заполнения, чтобы можно было одним действием заполнить выбранное поле для всех строк
- Нужна возможность быстро проставить порядковые номера

6. Превью нового имени
- Для каждой строки сразу отображать рассчитанное новое имя
- При изменении любого поля или шаблона превью должно обновляться автоматически

7. Валидация
- Перед экспортом нужно проверить:
  - нет ли пустых итоговых имен
  - нет ли дубликатов имен
  - нет ли запрещенных символов в имени файла: `\\ / : * ? \" < > |`
  - не потеряно ли расширение файла
- Ошибки должны красиво отображаться в интерфейсе

8. Экспорт
- После переименования пользователь может скачать новый ZIP
- В новый ZIP нужно положить исходные файлы, но уже с новыми именами
- Содержимое файлов менять не нужно
- Папки можно не сохранять, если это усложняет MVP, но лучше предусмотреть архитектуру для этого
- Использовать библиотеку `jszip`

9. UI/UX
- Сделай интерфейс современным, чистым, удобным
- Нужны:
  - зона загрузки архива
  - таблица файлов
  - редактор шаблона
  - блок массовых действий
  - панель ошибок/валидации
  - кнопка экспорта ZIP
- Желательно использовать аккуратные карточки, таблицу, адаптивные отступы
- Поддержать светлую тему
- Сделать UX понятным без лишней перегруженности

10. Технические требования к коду
- Используй TypeScript строго типизированно
- Раздели код на модули
- Не делай всё в одном файле
- Сделай понятную структуру проекта
- Вынеси отдельно:
  - типы
  - ZIP-логику
  - template engine
  - утилиты очистки имени
  - валидацию
  - UI-компоненты
- Код должен быть готов к реальному запуску после `npm install` и `npm run dev`

11. Библиотеки
Используй:
- `jszip` для ZIP
- `file-saver` для скачивания
- `@dnd-kit/core` и связанные пакеты для drag-and-drop
Можно использовать:
- `react-hook-form` если поможет
- любой легкий UI-подход, но без перегруза
Не использовать backend и серверную обработку
